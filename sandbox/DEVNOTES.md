# DEVNOTES · 迭代日志

> 记录每一轮「反馈 → 定位根因 → 修复 → 验证」的完整闭环。验证手段以**无头浏览器真实渲染 + 像素/几何探针**为主——这正是多模态（看截图）与长上下文（跨文件、跨轮次保持一致性）能力的直接证据。

---

## Round 1 · 展开感：讲台与抽屉需要「打开」的动画

**反馈**：讲解台和抽屉的东西应该有个动画效果展开。

**实现**
- 抽屉：`perspective + translate3d` 3D 滑出，登记卡从 `rotateX(-88°)` 翻起，文字三行错峰浮现
- 讲解稿：以底边为轴 `rotateX(-86°)` 铰链翻起 + `clip-path` 揭开，四条横线 `scaleX(0→1)` 波形拉出，末行手稿延迟 1.1s 弹出

**验证**：逐帧采样 opacity/clip-path 确认过渡中间态（0 → 0.44 → 0.79 → 0.97 → 1）；零脚本错误。

## Round 2 · 借用登记卡「显示不完整」

**反馈**：钥匙柜的使用登记打开显示不完整。

**定位（根因）**：登记卡是抽屉（64×40px）的子元素，抽屉带 `transform-style: preserve-3d` 和 `filter: brightness()`。Chromium 将带 filter 的 3D 父元素拍平并把子内容裁剪到父平面——96px 宽的卡片被抽屉盒「切掉」一块。这不是样式问题，是结构问题。

**修复**
1. 将登记卡移出抽屉，作为钥匙柜的直接子元素（独立 z-index），切断裁剪链
2. 重排为 142×127 的完整档案卡：标题 + 19:42 时间胶囊、物品/借出/备注三行字段、「已登记」印章、顶部胶带、虚线脚注
3. 动画改为「从抽屉口向右抽出」：`clip-path` 横向揭开 + 旋转回弹 + 字段逐条浮现

**验证**：`opacity 1 / clip-path inset(0px)`，7 个子节点全可见，`scrollHeight ≤ clientHeight`（无溢出）；特写截图逐区核对；关-开往返 opacity 0.13 → 1；全链路 15 项断言通过。

## Round 3 · 视觉电影化（P1）

**需求**：镜头、光尘、视差、拼豆对齐的「见证时刻」。

**实现**：摄像机层（`#scene` + `applyCam`：开场推镜 1.075→1、开柜 1.07、读稿 1.05、结局 0.96）、16 颗体积光尘、道具接触阴影、林晚轮廓光、四层鼠标视差、20 颗拼豆逐颗点亮、`prefers-reduced-motion` 全量降级。

**一个被截图纠偏的细节**：拼豆点睛第一版给豆子「加光晕」，但截图对比发现**暖色光晕落在近白纸面上对比度几乎为零**（肉眼不可辨）。改为让豆子本体变成琥珀色发光体（渐变换色 + 孔洞发光 + drop-shadow）。像素探针复测：暖色像素占比 0 → 9.7%，最大饱和度 0.77——从「数值上亮了」变成「看得出来亮了」。

**验证**：镜头 1.045→1 / 1.07 / 1.05 / 0.96；视差墙面 -1.6px vs 林晚 +3.6px；20/20 豆子点亮；回归 31 断言通过。

**目标**：让评委在 30 秒内看懂这个作品。

**验证**：31/31 断言通过，含完整演示巡演到达结局、三个状态跳转页、reduced-motion 降级、零控制台错误。

## Round 5 · P3 工程包：叙事数据表 / 迁移白名单 / 调试 API

**目标**：把「大文件可控」从口号变成结构。

- **叙事数据表 `SCRIPT`**：~60 条台词/旁白/提示从处理器里搬进单一文案源；`TOPICS` 存储声明化的回复分支（`reply` 只做三元选择），逻辑层零字符串
- **迁移白名单 `transitions`**：`nextLight / addTrust / placeDrawing / unlockCabinet / toggleCabinet / grantClue / enterEnding` 七个纯函数；线索的连带效果（阶段、信任）收进 `CLUE_EFFECTS` 表，处理器里的 9 处 `S.stage = Math.max(...)` / `S.trust = Math.min(...)` 全部删除
- **`?stage=` 跳转复用真实迁移链**：不再直接写状态，而是连续调用 `grantClue`/`transition`，与玩家路径完全一致（测试可以断言「跳转后 state 与真实通关路径一致」）
- **调试 API**：`?debug=1` 挂载 `window.__STARDUST__` + FPS/状态 HUD（rAF 计帧，HUD 300ms 节流）
- **体检**：`visibilitychange` 暂停动画、`contain: layout style paint`、低核心设备降载星点/尘埃
- **清理**：删除 `render()` 中永不成立的 `target === 'case'` 死分支；`buildBeadGrid` 去掉从未生效的 `cell` 参数

**验证**：38/38 断言（新增 7 条：HUD 可见、FPS 运行、API 挂载、API 跳转 state 一致、迁移白名单、visibility 暂停、API 重开）。重构前后全部 31 条旧断言零改动通过。

## Round 6 · 独立观测进程（Seed · Context Observatory）

**需求**：「能不能有 Langfuse 那样的架构，另开一个进程实时监测模型处理了什么上下文、什么任务？」

**实现（`observer/`，零依赖 Node）**
- `server.mjs`：HTTP + SSE（`/api/stream`）+ CORS（file:// 游戏可直连）+ JSONL 落盘
- `store.mjs`：环形缓冲、入库前脱敏（content/text/code/prompt > 40 字符 → chars + sha256 前 16 + 120 字预览，`STORE_RAW_CONTEXT=1` 才留原文）、任务聚合
- `dashboard.html`：实时时间线 + 任务卡（工具数 / 上下文文件+字符数 / token / 测试进度条 / 状态） + 搜索 / 暂停 / 任务过滤
- `langfuse.mjs`：Langfuse ingestion 映射（trace-create / generation-create 含 usage / tool 起止合成 span / score-create），`LANGFUSE_*` 环境变量开启，纯函数可测
- `sdk.mjs`：Agent 侧 30 行接入——`createTracer().task()` 后 `readContext / generation(fn) / tool(fn) / decision / test / score / end`，回调抛错先上报失败态再透传，observer 未启动只告警一次
- `demo.mjs`：基于 SDK 的脚本化任务事件流（--speed / --live 真实调用方舟）
- 游戏接入 `?observe=1`：4 个上报点（会话开始 / 线索步骤 / 结局 / 重置），CORS + keepalive，失败静默

**验证**
- observer 自测 20/20（入库、脱敏保真、聚合、SSE 推送、面板可访问、Langfuse 四类映射、SDK 完整事件链/usage 聚合/工具异常透传）
- SDK 版 demo 端到端：21 事件 / 2 任务均 success，测试 38/38、token 2790 正确聚合
- 端到端：无头浏览器打开 `?observe=1&play=1`，键盘调灯 → 面板 1.5s 内出现 `session.start` 与 `task.step(glassReflection)`，上下文快照携带 `lightAngle: 正中`
- 游戏 38/38 回归通过（未开 observe 时零开销）
- 面板截图 `docs/screens/observer.png`

**设计取舍**：面板是独立进程、纯静态页，不引框架不建库——面试现场 `npm start` + `npm run demo` 两条命令即可复现；Langfuse 只作为可选导出目标，断网也能完整演示。

## Round 7 · 星宿拼豆小游戏

**需求**：「给拼豆创建一个小游戏——在一块板子上拼一个星宿图，豆子能从豆库里选对应颜色，增加一点趣味性。」

**叙事化改造**：把「已完成的拼豆画」改成「小满只拼到一半的线稿」——玩家补完北斗七星，才配把画挂进主展柜。小游戏从装饰变成因果链的第一环。

**实现**
- **工作台**：11×11 暗色板 + 北斗七星线稿（13 格目标）；每格小圆点提示所需颜色
- **豆库六色**：暖黄 / 月白 / 星蓝 / 青碧 / 紫星 / 连珠——对应真实星色与连线，选色即变浮标预览
- **落豆**：点选颜色后点击或按住划过连续落豆；错色豆标红抖动且不计进度；撤销 / 清空 / 提示（提示自动选色并指出星名：「天璇 · 需要月白」）
- **键盘**：方向键移动光标、回车落豆、Esc 退出
- **完成反馈**：13 颗豆按序弹亮、板面泛琥珀光、信任 +1、场景里的画同步点亮；收好画后目标自动切到「拖到展柜旁」
- **主线接入**：未拼完时拖拽被引导进小游戏；`?stage=match` 等跳转自动视为已拼好；`?demo=1` 自动逐颗拼完再走后续剧情

**验证**
- E2E 45/45（新增 9 条：打开小游戏、豆库 6 色、线稿 13 格、错色不计进度、拼完解锁、进度满格、关闭后画已拼好、?stage=match 含 built、调试 API studio）
- 专项 DOM 审计：板 121 格 / 13 目标 / 线稿点色正确；提示选色指向天璇；键盘落豆生效；拼完 trust 2、目标文案切换正确；全程零控制台错误
- 演示模式重排时序（自动拼豆 ~2.4s），22 秒完整巡演回归通过
- 新截图：`docs/screens/studio.png`、`studio-done.png`

**设计取舍**：小游戏状态（板面/撤销栈/选中色）刻意不进叙事状态机，只有 `perlerBuilt` 这一个事实入库——小游戏可反复进出，主线因果保持干净；错色不设惩罚只标红，鼓励试错而不是劝退。
